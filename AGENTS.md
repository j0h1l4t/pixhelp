# AGENTS.md

## Project status
Scaffolded, not yet integrated: `specs.md` is the authoritative architecture blueprint (restructured — read it by **section name**, not number); `backend/` is the Python agent skeleton with unit-tested pure logic; `ui/` is a hand-written Flutter overlay skeleton; `spike/` holds the measurement harnesses (`spike/capture/` for the sensory pipeline, `spike/inference/` for the reasoning budget — both `results.md` files are versioned and are the evidence base for the specs); `bin/` holds tracked llama.cpp wrappers. End-to-end integration on the Windows machine is still pending.

## Target environment (drives every design choice)
- Target OS is **Windows**; the agent runs on a standard laptop with **no discrete GPU** (Intel Core i7-10510U, 4C/8T, AVX2/FMA/BMI2, **no AVX-512**, Intel UHD graphics, **8GB RAM**). Preserve the resource budget in the specs' *Resource Budget* section when adding dependencies.
- Dev/edit flow: launch WSL from PowerShell (`PS> wsl`), then run `opencode`. Source lives on the Windows filesystem; watch for CRLF/path issues.

## Architectural constraints to honor
- Single async **Python** backend (`asyncio`) merges screen capture + OCR + agent loop; do not split into microservices. Blocking calls (`grab`, WinRT OCR, JPEG encode) run via `asyncio.to_thread`/executor; **copy dxcam frames before any `await`** (buffer reuse).
- Heartbeat is a **fixed tick** (`heartbeat.interval_s` in `backend/config.yaml`, design range 5–10s); a still-running heartbeat **skips** the next tick (coalesces) — never queue. Hard **8s reasoning deadline**; consecutive deadline hits degrade vision → text-only.
- Screen capture via `dxcam` at low frequency. Always `grab(new_frame_only=False)` — plain `grab()` returns `None` on an idle desktop. Use `output_color="BGRA"` (no OpenCV).
- **Change-gate is mandatory** before OCR: numpy mean-abs-diff with a **mandatory `int16` cast** (uint8 subtraction wraps: `10-250==16`), optionally strided (`gate.stride`). Threshold is calibrated from the spike's `change-gate` benchmark rows / MAD bullet in `results.md` — keep `backend/config.yaml` in sync with those measurements.
- OCR via **WinRT** (`winrt-*` split packages, *not* legacy `winsdk`; *not* PaddleOCR). Convert frames with `SoftwareBitmap.CreateCopyFromBuffer`, not the JPEG→`BitmapDecoder` roundtrip. Measured full-screen 1080p: median 411–829ms, p95 up to ~1,070ms across runs — bitmap size is the only lever (`ocr.downscale`, `capture.region`); aggregation to ≤5 blocks is ~7–17ms and does not change recognition cost. Pin OCR languages from config, not the OS user profile.
- Local inference via **`llama.cpp`** HTTP server on `127.0.0.1:8080`, plain prebuilt **Windows CPU x64** binary (`llama-b11552-bin-win-cpu-x64` under `%LOCALAPPDATA%`) — **no C++ toolchain**, never compile from source, no OpenVINO/SYCL/Vulkan, no GPU-only Python runners (vLLM et al.).
- **Models of record:** `Qwen/Qwen3-VL-2B-Instruct-GGUF` (`Qwen3VL-2B-Instruct-Q4_K_M.gguf` + `mmproj-Qwen3VL-2B-Instruct-Q8_0.gguf` — **mmproj is mandatory to serve images**) and `Qwen/Qwen2.5-0.5B-Instruct-GGUF` (`qwen2.5-0.5b-instruct-q4_k_m.gguf`, text-only fallback). Pin local file paths; **no `-hf` resolution at runtime**.
- UI is a **Flutter desktop** click-through overlay (`ui/`, `window_manager` first: `setIgnoreMouseEvents`, `setBackgroundColor(transparent)`; add `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW` via FFI if needed), fed by the backend over a **token-authenticated WebSocket on loopback** (backend hosts; one client; latest-wins drops). Feedback rules are schema-validated JSON with cooldown/dedup — see the *Feedback-Rule Output Contract* section.
- Telemetry goes to a remote OTLP endpoint (no local Jaeger/Prometheus/Docker), **off by default**. **Never export or log OCR text, images, or window titles** — only latencies/token rates/error codes. The same scrubbing rule applies to *local* logs and artifacts (nothing screen-derived is written to disk).

## Conventions
- Python environments with **venv** (no conda), created by `python.exe -m venv env`:
  - Backend: `backend/env` via `backend/setup_env.ps1` — deps in `backend/requirements.txt` (`dxcam`, the seven `winrt-*` split packages, `Pillow`, `numpy`, `aiohttp` [llama-server HTTP client], `websockets` [Flutter-facing server], `pyyaml`, `opentelemetry-sdk`, `opentelemetry-exporter-otlp-proto-http` — the OTLP exporters are *not* in the SDK package). Keep this list in sync with the specs' *Minimalist Setup Requirements* section. **OpenCV is deliberately omitted.**
  - Spikes: **no spike-local venv** — `spike/capture/`, `spike/inference/` (and any future spike) run from `backend/env` (`..\..\backend\env\Scripts\python.exe bench_*.py` from the spike folder). Their imports are already in `backend/requirements.txt`; there are no per-spike `requirements.txt`/`setup_env.ps1` (removed — delete a stray `spike/*/env` if one appears). Spike-only extras, if ever needed, go into `backend/requirements-dev.txt`.
  - Dev tooling: `backend/requirements-dev.txt` (`pytest`, `ruff`).
- Runtime config lives in **`backend/config.yaml`** (single source of truth; invalid/unknown keys are fatal at startup; secrets via env vars named in the file, never inlined).
- **One log file** for the whole event flow: `backend/logs/pixhelp.log` (rotating, via the `logging` section of `config.yaml`; gitignored). Every heartbeat emits a `flow:` line with stage timings, and tick-skips are logged explicitly. The privacy scrubbing filter is attached to **all** log handlers — never log OCR text, frames, or window titles.
- Tests: pure-logic only, import-guarded so they run off-Windows too. Before considering a change done: `ruff check backend spike` and `python -m pytest backend/tests` (WSL `python3` with `numpy pyyaml pytest` works; the backend venv works on Windows).
- `bin/` wrappers are tracked source: bash variants for WSL (convert paths via `wslpath` — the `.exe`s cannot parse `/mnt/...`, including env values), `.ps1` variants for Windows-native. `spike/capture/results.md` is versioned; `ocr_sample.json` is gitignored (contains real screen text).
- **Privacy scrubbing applies everywhere**: keep the rule above enforced whenever touching telemetry, logging, or IPC code.
- **Privacy of tracked files (strict):** every file committed to the repo must be privacy-clean — no OCR text, screenshots/frames, window titles, IPC tokens, personal usernames/paths, or any other screen-derived or identifying content (specs.md §7). Sensitive data may exist **only in untracked files** (gitignored: `spike/*/ocr_sample.json`, `backend/logs/`, `backend/env/`, and any ad-hoc captures). Before committing: review `git status`/`git diff`, re-verify spike `results.md` files contain timings/counts only, and never print recognized text from harnesses (console output gets pasted into chats and commits). If unsure whether something is screen-derived, it is — leave it untracked.
